## Methodology

* Each (benchmark, library) pair runs in an isolated subprocess; *Peak RSS* is that process's `ru_maxrss` (imports + data), *RSS after imports* is the high-water mark right before the first timed run.
* Generator / factory setup and a tiny warm-up call are excluded from timing. Timed regions cover the whole user-visible operation (e.g. rows **and** DataFrame construction **and** Parquet write).
* nextfake: median of 5 runs. Competitors: median of up to 3 runs (1 run when a run takes ≥ 2 s).
* 1M-row competitor runs are probed at 100k rows; when the linear 1M estimate exceeds 60 s the extrapolated value is reported and marked *(extrap.)*, otherwise the full 1M rows are generated.
* `nextfake (1 thread)` uses `Faker(threads=1)` to separate algorithmic gains from multi-core parallelism. Output is identical for any thread count.
* Polyfactory (default) fills `full_name`/`city` with random strings; *Polyfactory + Faker fields* wires the same semantic Faker providers nextfake infers automatically, for an apples-to-apples comparison.
* Pydantic benchmarks validate every model (`EmailStr` validation via `email-validator` dominates nextfake's time there); `validate=False` uses `model_construct`.
